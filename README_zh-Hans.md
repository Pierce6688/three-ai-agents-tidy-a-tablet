# 三个 AI 代理联手整理一台平板

**一台 Mac、三个 AI 代理、一台小米平板 7 Pro：桌面从 4 页乱糟糟变成 2 页清爽——全程远程、无线 ADB。**

> 实战记录 + 可复现手册：三个共用一台 MacBook 的 AI 代理，如何隔空整理一台 Android 平板的桌面。

## 成员与分工

| 代理 | 运行位置 | 本次任务角色 |
|---|---|---|
| **Hermes**（Nous Research；Mac 常驻 AI 中枢） | macOS 常驻 | 总协调 + 唯一「有手的」：无线 ADB、屏幕读取、手势脚本、验收、记忆 |
| **ChatGPT**（GPT-6，桌面版） | macOS 桌面应用 | 参谋：提出分段拖拽方案、复核合并数学、协调者卡关时出第二意见 |
| **VS Code Copilot**（headless runtime） | macOS | 执行支援：代码生成、脚本起草、审阅 |

人类主人只提了一个需求——**「把桌面整理好：页页排满、没有空洞」**——然后验收成果。他没有指定谁做什么；派活由总协调判断。事后证明这不是图方便，而是设计原则（见「教训」）。

## 任务

- **目标设备**：小米平板 7 Pro（HyperOS 3 / Android 16）
- **通道**：Mac → 平板无线 ADB（该机此前 USB 配对过一次，密钥直接沿用——免插线、免重新配对）
- **整理前**：4 页桌面，约 40 个图标散落在处处空洞的页面
- **整理后**：2 页紧凑排列，零空洞

## 难在哪里

1. **平板没有「摇一摇补位」。** 小米手机摇一摇（或双指捏合）就能让图标靠拢填洞；平板版实测无此手势——摇了，没反应。内置的「卸载后自动补位」只管*以后*的卸载，管不了现成的洞。
2. **`adb shell input draganddrop` 太粗糙**：无法逐步验证，跨页拖拽不可靠。
3. **解法——用 `input motionevent` 脚本化手势**：长按抓起 → 分段 MOVE → 贴边悬停约 0.35 秒触发翻页 → 目标格落点。翻页与否靠桌面指示圆点的实时读取确认。
4. **地板一直在动。** HyperOS 在图标离开原格的瞬间就自动补位，先前量好的坐标全部作废。铁律：**搬一个 → 验一个 → 重读网格 → 再搬下一个。**

## 三方握手

开工前，三位代理先正式互相认识——双向都有程序化证据，无人工复制粘贴：

- 总协调 → Copilot：走 VS Code CLI，回复从 Copilot runtime 的 `events.jsonl` 读回
- 总协调 → ChatGPT 桌面版：走剪贴板 + UI 自动化，回复从 macOS 辅助功能树（`AXStaticText`）读回
- 再由总协调中继，Copilot ⇄ ChatGPT 互道招呼——每个方向都以「读回目标应用窗口里的真实文字」完成验证

值得记录的插曲：ChatGPT 桌面版**没有 API**，而「粘贴＋回车」常常*假成功*——按键回报成功，消息却悄悄没送出。可靠做法是对辅助功能树里的输入框元素直写，然后读回窗口内容确认。**别相信任何返回值；一切以读回为准。**

## 给代理团队的教训

1. **按能力派活，且由总协调派。** 用户提需求、验结果；谁做什么由总协调判断。让人类微观管理 AI 的分工，反而失去组队的意义。
2. **留一位圈外审查者。** 三个 AI 独处会形成回音室。人类随口的三句纠正（「Copilot 闲着」「ChatGPT 也会写代码」「别把我当调度员」）三次修正了系统设计。
3. **验证文化。** 「指令回报成功」不等于成功。无论图标网格、聊天窗口还是文件，都要读回确认。
4. **派单一次给足。** 派工作给代码导向代理时，第一条消息就附上路径、输入输出样例与验收标准——追问烧额度也烧时间。

## 复现

- 一台 Mac，终端有**辅助功能**权限（系统设置 → 隐私与安全性）
- VS Code + GitHub Copilot（其 headless runtime）、ChatGPT 桌面版
- 一台开启无线调试的 Android 平板；Mac 装有 `adb`
- 不 root、不装第三方桌面、不恢复出厂——全程只靠标准 ADB 输入注入与桌面自身设置
